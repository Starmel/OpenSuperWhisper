# Аудит багов OpenSuperWhisper — 30 июля 2026

## Краткий итог

Главный воспроизводимый дефект длинной диктовки локализован и исправлен.
Whisper возвращает внутренние decoder segments, а приложение добавляло перевод
строки после каждого из них. Для записей длиннее 30 секунд эти технические
границы становились видимыми абзацами.

Жёсткого лимита записи в одну или две минуты в приложении нет. Контекст между
30-секундными окнами Whisper включён (`noContext = false`), а все возвращённые
сегменты извлекаются последовательно. На тестовых записях длительностью 97 и
107 секунд начало, середина и хвост сохранились.

Кроме этого найдены более серьёзные lifecycle/concurrency-дефекты. Гонка отмены
и последовательного запуска, а также Esc во время decoding исправлены в ходе
работы. Первая транскрипция после onboarding всё ещё может использовать
незагруженный engine, а ошибка всё ещё удаляет единственную WAV-запись.

## Длинная диктовка

### Причина искусственных абзацев

Путь данных:

`ShortcutManager → IndicatorViewModel → AudioRecorder → TranscriptionService → WhisperEngine → Silero VAD → whisper.cpp → ClipboardUtil`

До исправления `WhisperEngine` безусловно выполнял эквивалент
`text += segmentText + "\n"` для каждого сегмента. Для тестовых файлов
whisper.cpp вернул:

- EN, 97,15 с: 4 сегмента, границы около 29,85 / 59,71 / 89,56 с;
- RU, 106,62 с: 4 сегмента, границы около 30,07 / 60,03 / 89,85 с.

То есть старый код создавал по три искусственных переноса. Теперь обычный режим
соединяет исходные тексты сегментов без разделителя; строки сохраняются только
в режиме таймкодов: [WhisperEngine.swift](../OpenSuperWhisper/Engines/WhisperEngine.swift#L199).

### Контекст и возможная потеря текста

- Контекст между окнами включён в
  [WhisperEngine.swift](../OpenSuperWhisper/Engines/WhisperEngine.swift#L130).
- Для каждой записи создаётся отдельный `whisper_state`, поэтому контекст не
  течёт из предыдущей записи.
- Параметры long-form декодирования теперь проверяются unit-тестом:
  `noContext = false`, а rolling context для tiny ограничен 224 токенами.
- Короткий `initialPrompt` переносится в последующие окна. Слишком длинный prompt
  больше не переносится каждый раз, если он оставил бы меньше половины бюджета
  предыдущей расшифровке.
- Подтверждённого clipping на границах конвертации в сценарии 1–2 минут не
  найдено; существующие тесты конвертера 3–15 секунд проходят.

Integration-тест получает сырые decoder segments из того же обычного пути с
VAD (`showTimestamps = false`) и проверяет все три стыка около 30/60/90 секунд.
Фразы действительно разрезаются границей и собираются непрерывно:

- EN: `middle | recording`, `during | conversion`;
- RU: `прежнему | обсуждаем`, `последнее | контрольная`.

Для русского стыка дополнительно проверяется порядок локальных слов вокруг
60-й секунды и отсутствие дублей. При отключённом rolling context этот блок
пропадает, поэтому новая проверка ловит регрессию, которую общий set-based
recall раньше пропускал.

Whisper использует ограниченное скользящее текстовое окно. Очень старые слова
многоминутной записи со временем перестают участвовать в conditioning, но уже
распознанный текст из результата не удаляется.

### Медиа и фактический результат

Добавлены фиксированные synthetic fixtures:

| Файл | Длительность | Формат | SHA-256 |
|---|---:|---|---|
| `long_en.m4a` | 97,1 с | AAC, mono, 16 kHz | `34c051c05fd076777903aae3694aef7386e9ad92126996cc3839655df1adf691` |
| `long_ru.m4a` | 106,6 с | AAC, mono, 16 kHz | `6af9e64b6fc78ee90860da0576632644bb804a5cbedb876c026f54f0e9448326` |

Полный путь приложения, включая аудиоконвертацию, Silero VAD и multilingual
`ggml-tiny.bin`, дал:

| Язык | Unique-word recall | Recall хвоста | Искусственные переносы |
|---|---:|---:|---:|
| EN | 0,980 | 0,977 | 0 |
| RU | 0,747 | 0,714 | 0 |

Тест дополнительно требует контрольную фразу из середины и уникальное слово из
последней четверти результата. Это не позволяет ранним повторяющимся словам
скрыть обрезанный хвост.

## Подтверждённые дефекты

### OSW-001 — decoder segments превращались в абзацы

- Приоритет: P1.
- Статус: исправлен в этом аудите.
- Доказательство: четыре сегмента на каждой длинной записи давали три видимых
  переноса.
- Регрессия: unit-тест на 240 EN/RU сегментов и два настоящих long-form
  integration-прогона.

### OSW-002 — первая запись после onboarding может не иметь загруженного engine

- Приоритет: P0, потому что следующий дефект превращает это в потерю записи.
- `TranscriptionService.init()` сразу запускает загрузку engine:
  [TranscriptionService.swift](../OpenSuperWhisper/TranscriptionService.swift#L24).
- Очередь создаёт этот singleton при старте приложения:
  [OpenSuperWhisperApp.swift](../OpenSuperWhisper/OpenSuperWhisperApp.swift#L62).
- На свежем профиле путь модели ещё не выбран, и загрузка завершается только
  сообщением в console.
- Выбор модели в onboarding записывает preferences, но не перезагружает engine:
  [OnboardingView.swift](../OpenSuperWhisper/Onboarding/OnboardingView.swift#L101).
- Кнопка Continue также лишь закрывает onboarding:
  [OnboardingView.swift](../OpenSuperWhisper/Onboarding/OnboardingView.swift#L501).
- Та же проблема затрагивает pending queue: она начинает обработку, не ожидая
  готовности engine, и может пометить записи как failed.

План исправления: сделать загрузку awaitable state machine (`idle/loading/ready/
failed`), передать ошибку в UI, на завершении onboarding вызвать и дождаться
reload, а queue запускать только после `ready`.

### OSW-003 — ошибка транскрипции удаляет единственную диктовку

- Приоритет: P0.
- При любой ошибке indicator-flow удаляет временный WAV:
  [IndicatorWindow.swift](../OpenSuperWhisper/Indicator/IndicatorWindow.swift#L199).
- Пользователь не видит actionable error; это также соответствует открытому
  [issue #117](https://github.com/Starmel/OpenSuperWhisper/issues/117).

План исправления: сначала создать history record и переместить WAV в постоянное
хранилище, затем транскрибировать. При ошибке оставить запись со статусом
`failed`, показать Retry / Reveal in Finder / Delete и хранить типизированную
причину ошибки.

### OSW-004 — гонка последовательной транскрипции и отмены

- Приоритет: P0/P1.
- Статус: исправлен.
- Каждая операция получила UUID и собственный engine/task box:
  [TranscriptionService.swift](../OpenSuperWhisper/TranscriptionService.swift#L15).
- Cancel больше не очищает active box и `isTranscribing` до фактического выхода
  native decoder. Следующий вызов ожидает завершения предыдущего.
- Cleanup и progress/result publication проверяют identity операции; поздний
  результат отменённой сессии не публикуется.
- Детерминированный blocking fake подтверждает `maxConcurrentCallCount == 1`,
  ожидание native return и игнорирование cancel с чужим UUID.

### OSW-005 — несколько импортов за одну секунду используют один audio filename

- Приоритет: P1.
- Очередь создаёт имя только из целых секунд:
  [TranscriptionQueue.swift](../OpenSuperWhisper/TranscriptionQueue.swift#L96).
- Второй файл удаляет уже существующий `finalURL` перед копированием:
  [TranscriptionQueue.swift](../OpenSuperWhisper/TranscriptionQueue.swift#L250).
- При multi-file drop две строки истории могут указывать на один и тот же
  последний аудиофайл; удаление одной строки ломает другую.

План исправления: использовать уже созданный UUID (`<uuid>.wav`) во всех трёх
recording flows и добавить тест одновременного импорта. Существующие
перезаписанные файлы автоматически восстановить невозможно.

### OSW-006 — FluidAudio v3 не получает выбранный язык

- Приоритет: P1 для multilingual диктовки.
- `settings.selectedLanguage` не передаётся в
  [FluidAudioEngine.swift](../OpenSuperWhisper/Engines/FluidAudioEngine.swift#L76),
  хотя FluidAudio 0.15.4 принимает `language:` и применяет script-aware token
  filtering.
- Поле `transcriptionTask` никогда не присваивается, поэтому его отмена ничего
  не отменяет.

План исправления: преобразовать код языка в `FluidAudio.Language`, передавать
hint для v3 (`auto → nil`), а cancellation связать с реально исполняемой
операцией. Добавить RU/EN test на language mapping и отдельный model smoke test.

### OSW-007 — перечисление микрофонов может блокировать запуск, Bluetooth-list устаревает

- Приоритет: P1.
- Singleton синхронно вызывает `AVCaptureDevice.DiscoverySession` в init:
  [MicrophoneService.swift](../OpenSuperWhisper/MicrophoneService.swift#L31).
- Он создаётся ещё до показа окна:
  [OpenSuperWhisperApp.swift](../OpenSuperWhisper/OpenSuperWhisperApp.swift#L54).
- Изменения устройств отслеживаются только через AVFoundation notifications,
  которые ненадёжны при переподключении Bluetooth:
  [MicrophoneService.swift](../OpenSuperWhisper/MicrophoneService.swift#L45).
- Воспроизведение с process sample описано в
  [issue #193](https://github.com/Starmel/OpenSuperWhisper/issues/193), stale
  AirPods — в [issue #179](https://github.com/Starmel/OpenSuperWhisper/issues/179).

План исправления: не выполнять enumeration на launch/main actor, показывать
placeholder state и слушать CoreAudio `kAudioHardwarePropertyDevices`; сохранять
выбор при кратковременно пустом списке и публиковать только реальные изменения.

### OSW-008 — асинхронные reload engine могут завершиться не в том порядке

- Приоритет: P1.
- Каждый `loadEngine()` создаёт независимый detached task без generation token:
  [TranscriptionService.swift](../OpenSuperWhisper/TranscriptionService.swift#L40).
- Более старый медленный load может завершиться после нового и заменить
  `currentEngine` моделью или типом, которые пользователь уже отменил.

План исправления: монотонный generation ID, отмена предыдущей загрузки и
публикация результата только при совпадении generation и текущих preferences.

### OSW-009 — CI не запускает XCTest

- Приоритет: P1 для качества релизов.
- Workflow выполняет только `./run.sh build`:
  [build.yml](../.github/workflows/build.yml).
- Старый `OpenSuperWhisperTests/test_audio.m4a` имеет размер один байт и нигде
  не используется.

План исправления:

1. На каждый PR запускать быстрые unit/media tests.
2. Отдельным cached job запускать long RU/EN test с pinned model checksum.
3. В dedicated job отсутствие модели должно быть failure, а не `XCTSkip`.
4. Удалить однобайтовый fixture после проверки внешних ссылок на него.

### OSW-010 — повторная регистрация language observer

- Приоритет: P3.
- Каждый rebuild status menu повторно вызывает `addObserver`:
  [OpenSuperWhisperApp.swift](../OpenSuperWhisper/OpenSuperWhisperApp.swift#L232).

План исправления: зарегистрировать observer один раз в
`applicationDidFinishLaunching`, хранить token и снять его при teardown.

### OSW-011 — Esc во время decoding скрывает UI, но не отменяет decode

- Приоритет: P1.
- Статус: исправлен.
- View model хранит decoding `Task` и UUID, а Esc отменяет Swift task и только
  соответствующую operation в `TranscriptionService`:
  [IndicatorWindow.swift](../OpenSuperWhisper/Indicator/IndicatorWindow.swift#L164).
- `WhisperEngine` передаёт thread-safe abort flag в whisper.cpp; отмена во время
  конвертации также проверяется между chunks, а VAD/decoder проверяют cancel до
  последующих стадий.
- После Esc исходный временный файл удаляется как явно отменённая диктовка, но
  поздний текст не сохраняется и не вставляется.
- Delegate передаёт originating view model; callback старой сессии не может
  скрыть новый indicator.

### OSW-012 — recorder сообщает успех, не проверяя `record()`

- Приоритет: P2.
- Возвращаемое значение `AVAudioRecorder.record() -> Bool` игнорируется, после
  чего UI безусловно переходит в recording:
  [AudioRecorder.swift](../OpenSuperWhisper/AudioRecorder.swift#L196).
- При исчезнувшем устройстве пользователь может видеть запись, хотя аудиопоток
  не стартовал. Для connection-monitoring также нет конечного timeout.

План исправления: сделать start типизированной async-операцией, проверять
результат `record()`, добавить timeout и единый failure transition. Unit-тест
должен использовать recorder factory, возвращающий `false`.

### OSW-013 — Delete All не синхронизирован с активной очередью

- Приоритет: P2.
- `deleteAllRecordings()` удаляет строки и готовые URL, но не отменяет и не
  дожидается `TranscriptionQueue`:
  [Recording.swift](../OpenSuperWhisper/Models/Recording.swift#L356).
- Активная операция после удаления может дописать файл для уже удалённой строки;
  принадлежащий приложению `sourceFileURL` также не удаляется. Результат —
  orphan WAV и рассинхронизация UI/БД.

План исправления: `cancelAllAndWait()` перед транзакционным удалением, явная
политика владения source/final URL и тест с приостановленным fake engine.

### OSW-014 — изначально пустой clipboard не восстанавливается

- Приоритет: P2.
- Пустой pasteboard представлен как `nil`:
  [ClipboardUtil.swift](../OpenSuperWhisper/Utils/ClipboardUtil.swift#L164).
- Restore планируется только для non-`nil` snapshot, поэтому после вставки в
  режиме «paste, но не copy» ранее пустой clipboard содержит транскрипцию.

План исправления: snapshot должен различать пустое состояние и ошибку чтения;
если `changeCount` не менялся, для пустого snapshot вызвать `clearContents()`.
Добавить unit-тест на именованном `NSPasteboard`.

## План работ

### Этап 1 — защита данных и готовность engine

1. Реализовать awaitable engine state и typed load error.
2. Исправить onboarding и startup queue.
3. Сохранять WAV до транскрипции и не удалять его при ошибке.
4. Добавить first-run и failed-decode integration tests.

Критерий готовности: ни одна записанная диктовка не теряется, а запись нельзя
начать с неготовым engine без явного состояния UI.

### Этап 2 — сериализация, cancellation и reload

Выполнено:

1. Сериализация active task с identity-checked cleanup.
2. Завершаемая cancellation без раннего освобождения engine.
3. Связь indicator decoding с session ID.
4. Fake-engine concurrency tests и реальный native-abort test.

Осталось: generation token для reload и отдельный Thread Sanitizer job.

Критерий готовности: одновременно исполняется ровно один native decode, старый
cleanup не меняет состояние новой операции.

### Этап 3 — целостность истории

1. Перейти на UUID filenames.
2. Синхронизировать Delete All с очередью и удалить owned source files.
3. Проверить multi-file drop, rapid retry и delete/regenerate.
4. Добавить диагностику существующих duplicate paths.

### Этап 4 — multilingual и устройства

1. Передать language hint в FluidAudio.
2. Перенести microphone discovery с launch path.
3. Добавить CoreAudio device-list listener и тестируемый inventory adapter.

### Этап 5 — CI

1. Быстрые XCTest на каждый PR.
2. Обязательный long-form job с pinned multilingual model.
3. Периодический 44,1/48 kHz speech-boundary test, clipboard Unicode test и
   sanitizer jobs.

consumers при очень большом Unicode-тексте. Обрезку в этом пути воспроизвести не
удалось, поэтому это не включено в подтверждённые дефекты.

Пять падений полного unit target устранены:

- Проверки Bluetooth передают transport type явно в тот же классификатор,
