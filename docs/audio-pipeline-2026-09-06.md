# Подготовка аудио до остановки записи

Проверено на Apple M1 Max, 64 ГБ, Xcode 26.4.1.

## Зависимости

| Компонент | До | После |
| --- | --- | --- |
| whisper.cpp | f049fff9 (1.9.1) | 371b5a75 (1.9.3) |
| ggml | версия из прежнего Whisper | 0.20.2 |
| FluidAudio | 0.15.4 | 0.15.6 |
| GRDB | 7.5.0 | 7.11.1 |
| KeyboardShortcuts | 2.3.0 | 3.0.1 |
| autocorrect | 2.14.3, форк со Swift-обёрткой | 2.16.3, официальный исходник |

Существующая C/Swift-обёртка autocorrect перенесена из форка в
`libautocorrect`. Rust-зависимости зафиксированы в Cargo.lock. Оба
Package.resolved синхронизированы. Менеджер горячих клавиш адаптирован
к MainActor и переименованию `default` в `initial` в KeyboardShortcuts 3.

## Обработка записи

1. Модель Whisper и Silero VAD загружаются при инициализации движка.
2. После начала захвата сервис асинхронно готовит чистое состояние Whisper,
   если движок свободен. Распознавание дожидается этой подготовки; параллельный
   доступ к используемому состоянию запрещён.
3. AVAudioEngine передаёт копии PCM-буферов в отдельную последовательную очередь.
   Один AVAudioConverter сохраняет состояние между буферами, преобразует звук
   в 16 кГц / Int16 и записывает WAV. Те же сэмплы переводятся в Float32 в памяти.
4. После Stop сохраняется защитный хвост 250 мс. Очередь захвата завершается,
   ресемплер отдаёт оставшиеся сэмплы, WAV закрывается.
5. Whisper получает подготовленный PCM без повторного чтения WAV.
   Для нескольких каналов окончательное смешивание остаётся после Stop,
   чтобы сохранить прежний выбор активных каналов на тех же диапазонах аудио.
6. VAD, параметры декодирования и полный финальный проход Whisper сохранены.
   Состояние освобождается после каждой обработки, включая тишину и ошибки.

Файлы в очереди и FluidAudio продолжают использовать файловый вход. Весá
Whisper, beam size, язык и пороги распознавания не изменены. Потоковое
распознавание и Core ML для Whisper не включались.

## Проверки

- До изменений: 196 тестов, 43 пропуска, 0 ошибок.
- После обновления зависимостей: 197 тестов, 43 пропуска, 0 ошибок.
- После подготовки состояния и загрузки VAD: целевые проверки подготовки,
  отмены, изоляции состояния, тишины и длинной речи прошли перед каждым коммитом.
- Полный Debug-прогон после PCM: 204 теста, 44 пропуска, 0 ошибок.
- Release: 13 целевых тестов, 1 пропуск микрофона, 0 ошибок. Дополнительная
  проверка трёх чередующихся пар WAV/PCM через TranscriptionService также прошла.
- Подготовленный PCM побитово совпадает с чтением сохранённого WAV при
  16 / 44,1 / 48 кГц на входе и 1 / 2 / 4 каналах в проверенных сочетаниях.
- Проверяются длительность, наличие звука в хвосте, границы входных буферов,
  прямое распознавание PCM при несуществующем пути файла и совпадение текста
  между файловым и подготовленным входом.
- large-v3-turbo, beam 5: WER на длинных синтетических фикстурах составляет
  12,67% для английского и 7,02% для русского. Эти показатели не изменились
  после подготовки состояния, загрузки VAD и добавления PCM-входа.
- Тест живого микрофона требует `OSW_TEST_MICROPHONE=1` и разрешения macOS
  тестовому приложению. На этой машине разрешения нет, поэтому он пропущен.
  Остальные пропуски существовали до изменений и зависят от окружения.

Отдельный исходный запуск старого long-form теста на Turbo с greedy выявил
потерю конечной русской фразы и несовпадение ожидаемых границ сегментов ещё
до обновления. Проверки этого теста сохранены; стандартный прогон использует
multilingual tiny. Для Turbo добавлена отдельная проверка с пользовательским
beam 5, WER и конечной фразой, без привязки к сегментации tiny.

## Время

Один Debug-замер на длинной русской записи: файловый путь 10,825 с,
предварительное создание состояния 0,046 с, готовый PCM с подготовленным
состоянием 10,640 с. Подготовка выполняется до Stop и не входит в последнее
число. Это единичный замер, а не доказательство стабильного процентного
ускорения. Основная стоимость полного декодирования остаётся.

Первый одиночный Release-замер дал обратный результат: 4,722 с через файл и
5,060 с через PCM. Поэтому выполнены три чередующиеся пары через
TranscriptionService с приоритетом userInitiated, как в приложении:

| Путь | Три измерения, с | Медиана, с |
| --- | --- | --- |
| WAV | 4,430; 4,324; 4,219 | 4,324 |
| Готовый PCM | 4,191; 4,279; 4,272 | 4,272 |

Создание состояния до Stop занимало 18–19 мс в этой серии. Медианная разница
составила около 52 мс (1,2%); выборка мала, поэтому это не универсальная
оценка ускорения. Во всех трёх парах текст совпал полностью.

На момент проверки запущенный пользователем процесс находится в
`build/Build/Products/Debug/OpenSuperWhisper.app`. Он использует старую сборку.
Release на контрольной записи существенно быстрее Debug; при оценке
производительности следует запускать новую Release-сборку из системной
DerivedData. Работающий экземпляр приложения автоматически не перезапускался.

Для следующего сравнения Metal и Core ML нужны повторные Release-замеры
на одинаковом PCM, той же модели, beam 5 и языке, отдельно для загрузки,
энкодера, декодера и полной задержки после Stop. Совпадение качества следует
проверять на тех же эталонах и реальной диктовке.

## Запуск

Xcode использует стандартную системную DerivedData. Для Turbo-проверок:

```sh
rtk proxy env TEST_RUNNER_OSW_TEST_TURBO_MODEL=/absolute/path/ggml-large-v3-turbo.bin \
  xcodebuild test -project OpenSuperWhisper.xcodeproj -scheme OpenSuperWhisper \
  -configuration Release -destination 'platform=macOS,arch=arm64' \
  -parallel-testing-enabled NO -only-testing:OpenSuperWhisperTests \
  -clonedSourcePackagesDirPath SourcePackages CODE_SIGNING_ALLOWED=NO ENABLE_TESTABILITY=YES
```
